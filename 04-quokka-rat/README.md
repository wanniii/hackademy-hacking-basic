# 04 · Quokka RAT (트로이목마) — 개념 · 방어 중심 (실습 코드 제외)

> ⚠️ **스코프 안내.** 이 과정 원문은 리버스 쉘 → 페이로드 → 트로이목마 위장 →
> **지속성(persistence)** → **타 OS/Windows 배포 패키징**까지, 실제로 배포 가능한
> 악성코드를 만드는 내용을 포함한다. 이 저장소에서는 **교육·방어 목적**에 맞게
> **개념 설명 + 탐지/방어 안내**만 다룬다.
>
> 리버스 쉘·페이로드·지속성·트로이목마 위장·안티탐지·피해자 배포 패키징 등
> **동작하는 악성코드는 코드로 만들지 않고, 원리만 글로 설명**한다.
> (남의 컴퓨터를 몰래 제어하는 결과물을 저장소에 남기지 않기 위함이다.)
> 실행 가능한 데모/리스너/에이전트 스크립트는 이 폴더에 포함하지 않는다.

## 1. 악성코드와 RAT

- **악성코드(Malware)**: 사용자의 의도·이익에 반해 동작하도록 만든 프로그램.
- **트로이목마(Trojan)**: 정상 프로그램인 척 위장해 사용자가 스스로 실행하게 만드는 악성코드.
  (그리스 신화의 트로이 목마처럼 "선물"로 위장해 안으로 들어간다.)
- **RAT (Remote Access Trojan)**: 감염된 컴퓨터를 **원격에서 제어**할 수 있게 하는 악성코드.
  공격자는 피해자 PC에서 명령 실행·파일 열람 등을 원격으로 수행한다.

실제 사례로는 아이폰을 노린 상용 스파이웨어 Pegasus 등이 있다.

## 2. C2 모델 — 공격자 서버 ↔ 피해자

RAT은 보통 **C2(Command & Control)** 구조를 가진다. 공격자 서버가 명령을 내리고,
감염된 에이전트가 이를 받아 실행한 뒤 결과를 돌려보낸다.

```
[공격자 서버]  <----- 네트워크 ----->  [피해자 에이전트]
  명령 전송    ------------------>     명령 수신·실행
  결과 수신    <------------------     결과 전송
```

방어 관점의 포인트: C2는 **네트워크 통신**을 반드시 동반한다. 즉, 아웃바운드 연결과
주기적(비콘) 트래픽을 감시하면 탐지의 실마리가 된다 → [defense.md](defense.md)

## 3. 바인드 쉘 vs 리버스 쉘 (연결 방향의 개념)

원격에서 명령을 주고받는 "쉘"을 네트워크로 여는 방식은 크게 두 가지다.

| 구분 | 연결 방향 | 특징 |
|---|---|---|
| **바인드 쉘(Bind shell)** | 공격자 → 피해자 (피해자가 포트 Listen) | 피해자가 포트를 열고 대기. 방화벽/NAT에 자주 막힘 |
| **리버스 쉘(Reverse shell)** | 피해자 → 공격자 (공격자가 Listen) | 피해자가 밖으로 **나가는** 연결. 아웃바운드는 보통 허용돼 실전에서 더 흔함 |

RAT이 리버스 쉘을 선호하는 이유: 피해자 PC는 대개 NAT 뒤에 있어 외부에서 직접
접속(바인드)하기 어렵지만, 피해자가 밖으로 나가는 연결은 방화벽이 잘 막지 않기 때문이다.

→ 그래서 방어 측은 **들어오는 연결**뿐 아니라 **나가는(아웃바운드) 연결**을 반드시
함께 감시해야 한다. (상세: [defense.md](defense.md))

## 4. 명령 실행의 원리 (코드 없이)

RAT 에이전트의 핵심 동작은 "네트워크로 받은 문자열을 OS 명령으로 실행하고 그 결과를
공격자에게 돌려주는 것"이다. 많은 언어/런타임에 있는 **프로세스 실행 기능**
(예: 프로세스 생성 API, 셸 호출 기능)을 악용하는데, 이 기능 자체는 정상적인
자동화·빌드·배포에도 널리 쓰인다. 즉 **기능이 문제가 아니라, "신뢰할 수 없는 원격
입력을 그대로 명령으로 실행"하는 사용 방식**이 악성 행위를 만든다.

> 이 저장소는 실제로 명령을 수신·실행하는 에이전트 코드를 제공하지 않는다.
> 방어 측에서 중요한 것은 "어떤 프로세스가 네트워크 입력을 받아 자식 프로세스
> (셸·스크립트 해석기 등)를 생성하는가"를 탐지하는 것이다 → [defense.md](defense.md)

## 5. 공격자의 무기화(weaponization) 단계 — 원리만

"개념 확인용 코드"가 **실제 악성코드**로 바뀌는 지점이 바로 아래 단계들이다.
이 저장소는 이를 **코드로 구현하지 않고 원리와 방어 관점만** 서술한다.

- **페이로드/트로이목마 위장**: 원격 제어 기능을 정상 앱(설치파일·문서·게임 등)에
  끼워 넣어 사용자가 스스로 실행하게 유도한다.
  → 방어: 코드 서명 검증, 출처 불명 실행파일 차단, 문서 매크로 비활성화, 사용자 교육.
- **지속성(Persistence)**: 재부팅 후에도 살아남도록 자동시작 지점에 자신을 등록한다
  (리눅스 cron, Windows 레지스트리 Run 키·예약작업·서비스, macOS launchd 등).
  → 방어: 자동시작 지점 정기 점검, 변경 모니터링(다음 문서에 체크리스트).
- **배포 패키징**: 대상 OS에서 별도 런타임 없이도 실행되도록 단일 실행파일로 묶는다.
  → 방어: EDR의 실행파일 평판·행위 기반 탐지, 최소권한 실행.

→ 이 단계들이 "장난 코드"를 **실제 악성코드**로 바꾸는 지점이다. 그래서 방어가 중요하다.
