# 04 · Quokka RAT (트로이목마) — 개념 · 방어 중심

> ⚠️ **스코프 안내.** 이 과정 원문은 리버스 쉘 → 페이로드 → 트로이목마 위장 →
> **지속성(persistence)** → **타 OS/Windows 배포 패키징**까지, 실제 배포 가능한 악성코드를
> 만드는 내용을 포함한다. 이 저장소에서는 **교육·방어 목적**에 맞게,
> **개념 설명 + localhost 전용 최소 데모 + 탐지/방어**까지만 다룬다.
> 지속성·트로이목마 위장·안티탐지·피해자 배포 패키징 등 **무기화에 해당하는 부분은
> 코드로 만들지 않고 원리만 글로 설명**한다. (남의 컴퓨터를 몰래 제어하는 결과물을 남기지 않기 위함)

## 1. 악성코드와 RAT

- **악성코드(Malware)**: 사용자의 의도·이익에 반해 동작하도록 만든 프로그램.
- **트로이목마(Trojan)**: 정상 프로그램인 척 위장해 사용자가 스스로 실행하게 만드는 악성코드.
  (그리스 신화의 트로이 목마처럼, "선물"로 위장해 안으로 들어간다.)
- **RAT (Remote Access Trojan)**: 감염된 컴퓨터를 **원격에서 제어**할 수 있게 하는 악성코드.
  공격자는 피해자 PC에서 명령 실행, 파일 열람 등을 원격으로 한다.

실제 사례로는 아이폰을 노린 상용 스파이웨어 Pegasus 등이 있다.

## 2. C2 모델 — 공격자 서버 ↔ 피해자

RAT은 보통 **C2(Command & Control)** 구조를 가진다.

```
[공격자 서버]  <----- 네트워크 ----->  [피해자 에이전트]
  명령 전송    ------------------>     명령 수신·실행
  결과 수신    <------------------     결과 전송
```

## 3. 바인드 쉘 vs 리버스 쉘

명령을 주고받는 "쉘"을 네트워크로 여는 방식 두 가지:

| | 연결 방향 | 특징 |
|---|---|---|
| **바인드 쉘(Bind shell)** | 공격자 → 피해자 (피해자가 포트 Listen) | 피해자가 포트를 열고 대기. 방화벽/NAT에 자주 막힘 |
| **리버스 쉘(Reverse shell)** | 피해자 → 공격자 (공격자가 Listen) | 피해자가 밖으로 **나가는** 연결. 아웃바운드는 보통 허용돼 실전에서 더 흔함 |

RAT이 리버스 쉘을 선호하는 이유: 피해자 PC는 대개 NAT 뒤에 있어 외부에서 직접
접속(바인드)하기 어렵지만, 피해자가 밖으로 나가는 연결은 방화벽이 잘 막지 않기 때문.

## 4. subprocess — 파이썬에서 쉘 명령 실행

RAT의 핵심은 "받은 문자열을 OS 명령으로 실행하고 결과를 돌려주는 것"이다.
파이썬에서는 `subprocess` 모듈로 한다 (이 자체는 정상적인 자동화에도 쓰이는 기능):

```python
import subprocess
out = subprocess.run(["id"], capture_output=True, text=True).stdout
```

## 5. localhost 전용 최소 데모 (개념 확인용)

`demo/`의 두 스크립트는 **같은 컴퓨터 안(127.0.0.1)에서만** 도는 개념 설명용이다.
"소켓으로 명령이 오가고 subprocess로 실행된다"는 메커니즘만 보여준다.

```bash
# 터미널 A (공격자 역할, listener)
python demo/listener.py
# 터미널 B (피해자 역할, agent)  — 127.0.0.1 로만 연결됨
python demo/agent.py
```

→ listener에서 `whoami`, `pwd` 등을 입력하면 agent 쪽에서 실행되어 결과가 돌아온다.
자세한 제약은 각 파일 상단 주석 참고. **실제 원격/타인 PC 대상 사용 금지.**

## 6. 공격자가 하는 무기화 단계 (개념만)

원문은 아래로 이어지지만, 이 저장소는 **코드로 구현하지 않고 원리만** 적는다.

- **페이로드/트로이목마 위장**: 리버스 쉘을 정상 앱(설치파일·문서·게임 등)에 끼워 넣어
  사용자가 스스로 실행하게 유도.
- **지속성(Persistence)**: 재부팅 후에도 살아남도록 자동시작 등록(cron, 레지스트리 Run 키,
  서비스/시작프로그램, launchd 등)에 자신을 등록.
- **배포 패키징**: 대상 OS에서 인터프리터 없이도 돌도록 실행파일로 묶음(예: Windows embedded Python).

→ 이 단계들이 "장난 코드"를 **실제 악성코드**로 바꾸는 지점이다. 그래서 방어가 중요하다.
